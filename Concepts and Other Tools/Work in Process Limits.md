- **Work in Process (WIP)**: Work that has been started but is not yet finished.
- **WIP Limit**: A maximum number of items allowed in a workflow stage at one time.

## Why WIP limits matter

Starting many items at once does not necessarily increase throughput. Too much WIP creates delays, context switching, hidden blockers, and unfinished work.

WIP limits expose bottlenecks so the team can improve the system instead of starting even more work.

## Pull system

WIP limits create a pull system. A team starts new work only when there is available capacity, usually after finishing or moving existing work forward.

The goal is to finish work before starting more work.

## Five thieves of time

- Too much work in process.
- Conflicting priorities.
- Unknown dependencies.
- Unplanned work.
- Neglected work.

These problems increase delays and make flow less predictable.

## Use WIP limits with other practices

WIP limits work best with:

- Visible workflow boards.
- Production monitoring and feedback loops.
- Clear priorities.
- Small batches of work.
- Team collaboration or swarming to unblock work.

## Key idea

When a WIP limit is reached, do not start another item. Help move existing work to done, remove the blocker, or improve the workflow.
